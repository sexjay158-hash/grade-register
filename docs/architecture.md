# 代码结构与扩展约定

本项目使用 React、Vinext、Cloudflare Worker、D1 和 R2。现有业务保留在同一应用中，按职责逐步拆分，避免为了换架构同时重写已验证的权限和事务逻辑。

## 从哪里开始

| 位置 | 职责 | 后续修改原则 |
| --- | --- | --- |
| `app/api/**/route.ts` | HTTP、身份校验、参数校验、返回结果 | 新增复杂逻辑放进服务模块，避免路由继续增长 |
| `lib/workspace/read-state.ts` | 工作台的批量数据库查询 | 读取限定学期；不跨请求缓存业务结果 |
| `lib/workspace/projection.ts` | 各角色可见数据和统计 | 纯函数；新角色或新统计在这里添加测试 |
| `lib/workspace/types.ts` | 工作台查询边界的数据类型 | 数据库额外字段原样传递，扩展时明确必需字段 |
| `lib/http.ts` | 有界 JSON 解析、响应、错误编号 | 新业务异常用 `HttpError(status, code, message)` |
| `lib/guarded-batch.ts` | 在同一事务内验证写入条件 | 检查身份、学院、学期、活动版本与变更一起提交 |
| `lib/session-store.ts` | 会话与改密的原子更新 | 不单独撤销、重建会话以免产生竞态 |
| `lib/*cohort*`、`role-scope.ts` | 小组负责年级和权限范围 | 学号年份和小组负责年级是不同概念 |
| `app/roster-manager.tsx` 等 | 各业务界面 | 页面状态就近管理，异步返回需防止覆盖新范围 |
| `lib/browser-request.ts` | 超时、取消、安全读取重试 | 写请求结果不明确时不能自动重复提交 |
| `lib/flags.ts` | 集中功能开关 | 开关用于受控回退，不能替代后端授权 |
| `drizzle/*.sql` | 顺序执行的数据库迁移 | 不修改已发布迁移；新增迁移必须在空库验证 |
| `scripts/check.mjs` | 一次运行完整质量检查 | 检查失败即停止，不能略过失败后宣称通过 |

`app/workspace.tsx`、活动和学生部分路由仍含较多历史逻辑；本次没有冒险整体重写。后续增加功能时按上表从原模块提取服务与组件，并保留接口和数据库结构兼容。

## 必须保留的业务约束

- 年级负责人按小组的负责年级管理学生，少数跨年级学生随组；不直接用学号截断来做最终授权。
- 管理员、院负责人和年级负责人读取同一份数据；权限范围每次请求重新判断。
- 院负责人确认后，年级负责人不能改分；归档学期不可写入。
- 学号允许重复、允许后续改正。内部学生标识与显示学号不能混用。
- 删除照片保留归档、权限、已关联活动和已有成绩的保护。
- 删除、导入、改分与归档等多语句操作必须使用事务，并在事务内再次验证前置条件。
- 不把账号、学号、照片、密钥或请求正文写进错误日志。

## 新功能的落地顺序

先确认角色和学期范围，定义输入输出，再写独立领域函数和服务；路由只连接鉴权、校验与服务。为越权、归档、并发冲突各补一个真实场景测试，运行 `npm run check`。涉及权限或成绩的变化不能只验证页面按钮是否隐藏。

数据库当前还包含兼容旧版的运行时建表/索引初始化。新的结构优先采用显式迁移；删除旧兼容逻辑前需要专门的数据迁移和恢复演练，不直接清理历史表。

## 性能边界

工作台统计使用 Map/Set 索引，避免对每个活动、每张照片反复扫描完整成绩和照片列表；照片操作者查询限定当前学期，管理员无需读取这份辅助数据。响应仍返回当前范围的完整名单和成绩，没有改成分页接口。以后数据增长到加载过慢时，应加服务端分页、筛选和按需明细接口，并调整前端，不能只扩大请求限制。

这次结构调整不代表已提高服务器并发上限。OCR 的计算、手机内存、数据库配额和部署资源仍分别影响稳定性。
