# 学院统一开通小组账号

本功能仅更新本地项目，未正式发布。推荐每组开一个组长账号，无须为两万名学生逐一开户：一千个小组约需一千个小组账号，另外开院负责人、管理员账号；原年级负责人账号继续保留。

## 操作顺序

1. 管理员建立学院、学期，给各院负责人开账号。院负责人只能管理本院。
2. 院负责人审核本学期学生名单，先导入正式名单，确保每个组长在相应小组中。普通组员不需要注册系统账号。
3. 进入“本院账号”（管理员进入“人员权限”），选择开户学期，下载“小组负责人收集模板”。收集学号、姓名、学院、小组名称；入学年级可留空，系统使用该组负责年级。学号列应在 Excel 中设为文本，保留前导零。
4. 导入填写后的 Excel，检查预览。系统核对学号、姓名、学院、小组与正式名单；重复学号、重复组长分配、跨学院和账号冲突会提示错误。可以下载完整错误清单。每次最多 2000 名组长。
5. 点击“确认批量开通”，自动按每批 25 人提交。中断后重新预览同一文件，已有绑定会跳过，不会重复创建账号。前面成功的批次保留。
6. 下载本次激活信息，将对应行的学号、激活网址、一次性激活码分别给本人。不要把整份激活码表发到群里。下载完成后点击“已保存，清除显示”，再离开账号页。系统不会代发微信、短信或邮件。
7. 组长打开同一个网站的 `/activate`，输入学号、激活码，设置至少六位密码。激活码七天有效、仅可使用一次；激活后自动进入系统。以后从 `/login` 用学号和自己设置的密码登录。
8. 组长上传本组照片或手动补录，核对分数和等次后保存草稿；院负责人统一核对并确认。确认后组长不能自行改分，管理员与院负责人仍可按原流程处理。

已有“小组报名”中的审核通过名单，也可点击“使用已审核报名的组长”生成开户预览。旧报名页面的报名账号与正式成绩账号是不同用途：报名通过不会自动获得成绩权限，正式成绩账号仍须院负责人统一开通。使用 Excel 收集流程时，不需要先去报名页面注册。

## 权限和账号维护

| 身份 | 数据范围 | 账号操作 |
| --- | --- | --- |
| 学校管理员 | 全校 | 管理院负责人、年级负责人和全部小组账号 |
| 院负责人 | 本院全部年级、小组 | 按审核名单开通、重置、停用、交接本院小组账号 |
| 小组录入员 | 指定学期的指定小组 | 上传、核对、保存本组草稿；无权改正式名单或开户 |

小组权限由服务器检查，不只是在页面隐藏按钮。同院同年级的别组、外院、其他学期、照片和导出都遵循同样范围。照片出现其他组成员时，组长账号只录入自己负责组的匹配成绩；未出现的人不补零。学院负责人可按原流程处理本院混合小组照片。

- 丢失或过期激活码、忘记密码：院负责人点击“重新发激活码”。旧登录会话和旧密码立即失效，新码只在本次生成时提供。
- 暂停使用：点击“停用”，立即撤销所有设备登录；成绩历史保留。需要恢复时重新发激活码。
- 更换组长：点击“交接组长”，解除原负责关系并停用原账号，再导入新组长。旧活动与成绩不删除；同一学号办理交接后可以重新分配。
- 新学期沿用同一组长：先在旧学期交接解除绑定，再在新学期正式名单中导入。一个小组账号当前只绑定一个学期、一个小组。若旧学期已归档，管理员需先临时恢复旧学期、完成交接，再重新归档；历史成绩不受影响。
- 激活时遇到限流：页面显示等待并在五分钟以内有上限地重试；只重试明确尚未执行的“繁忙”响应。网络中断、超时不会盲目重放激活请求，可先尝试使用刚设的密码登录，仍不成功时联系院负责人。

账号批量导入每批原子写入。数据库仅存密码加盐哈希、激活码摘要，不保存明文激活码；管理接口不会返回以前的码。操作写入账号审计记录。

## 测试与容量边界

执行 `npm run verify:group-accounts` 可重跑本轮验收：生产构建、独立数据库迁移、两万人/一千组、批量开户、实际账号激活、权限隔离、入分折算、重置停用交接、并发读取及合成图片上传。报告默认在 `D:\课外锻炼\reports\group-accounts-20261023`。测试库和合成图片在结束时清理，不改日常数据。

该测试不等于“两万人同时在线”，也不提供手写照片识别率。上线前仍需用真实样表、真实手机和目标服务器复测；千人同一时刻首次登录会受密码计算和限流约束，应按学院错峰激活。临时外网验收仍依赖电脑运行和临时连接。
