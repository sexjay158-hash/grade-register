# 已识别照片删除

“照片自动识别情况”中，已识别且全部关联活动仍为草稿的照片可点击“删除照片”。确认框说明：删除原图及照片识别记录，保留已录入的成绩、活动等次、活动编号与历史审计。删除后可在上传区重新上传同一张或新的照片。

替换照片不会自动覆盖旧成绩。新照片与已有成绩不同仍进入原有冲突核对流程，需要到“核对成绩”修改，避免误覆盖手工录入。照片删除会增加所有关联活动的版本号，并留下 `delete_photo` 审计记录；已经打开的旧版本编辑页需刷新。

管理员可处理全校范围，学院负责人、年级负责人只能处理自己完整负责范围内的照片。跨学院或跨负责年级的同一张照片不允许局部管理者删除。共享但只读的未归组照片仍保持原有上传者保护。

已确认活动的照片禁止删除；混合照片只要有一个关联活动已确认，整张照片都不能删除。归档学期、归档学院及停用或变更权限账号的保护仍然生效。服务端在同一数据库事务内复查活动状态、版本、范围和学期，检查失败不删除关联或原图。

数据库事务成功后清理照片对象；对象清理失败会在页面明确提示，不能把列表删除当作对象已成功清理。网络请求结果不明确时先刷新核对，避免重复操作。

## 回退

将 `lib/flags.ts` 中 `recognizedPhotoDeletion` 改成 `false`，重新构建发布，即可关闭已识别照片删除，未识别照片删除继续由原开关控制。关闭功能不能找回已经删除的原图；恢复原图需要相应业务数据备份。

修改前源码快照：`../backups/source-before-recognized-photo-delete-20261022-001903.zip`。新逻辑位于 `lib/delete-recognized-photo.ts`，删除 API 在 `app/api/intake/route.ts`，页面入口在 `app/intake-workflow.tsx`，确认框复用 `app/delete-unrecognized-photo.tsx`。源码回退时保留现有业务数据库和照片存储。
