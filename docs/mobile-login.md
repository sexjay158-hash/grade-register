# 手机登录与慢网进入修复

登录页默认使用服务端输出的普通 POST 表单，账号和密码始终在请求正文中提交，不出现在网址里。无需等待客户端脚本下载、React 接管表单或账号状态请求，服务端认证成功后直接跳转到首页。浏览器自动填充也直接读取真实输入框。

原 JSON 登录接口继续用于既有客户端。普通表单复用相同的密码校验、账号停用检查、会话、登录限流及同源校验。登录繁忙、密码错误、次数限制和服务异常显示明确提示，不自动重复结果未知的登录请求。表单正文按流限制为 4096 字节。

工作台自动刷新必须等首次初始化成功后才能启动。此前选择学期后就会启动刷新，弱网下可能在首次 state 请求完成前发起第二次请求，导致首次结果被过期请求检查丢弃，页面却一直等待初始化完成。现在首次加载与后台刷新不再竞争；初始化后仍保留定时同步和切回页面刷新。去除每次创建定时器就立即刷新产生的多余请求。

实际临时外网入口测试中，登录页一次请求约 5 秒，说明临时隧道和网络仍有延迟。本修复解除登录对脚本加载的依赖，不承诺修复运营商、临时隧道或所有手机浏览器问题。短时本地测试不等于真实手机公网长时间稳定性证明。

`lib/flags.ts` 中 `nativeMobileLogin=false` 并重新构建，可恢复旧的脚本登录表单；初始化与自动刷新隔离修复继续保留。修改前源码快照：项目父目录 `backups/source-before-mobile-login-20261021-233350.zip`，已验证压缩包，不包含业务数据库和照片。

验证：83 项单元测试、TypeScript、正式构建、三角色集成及并发写入回归通过。原生 POST 集成确认会话有效且跳转成功；测试检查跨站拒绝、输入限额、特殊字符、错误提示及不重复登录写入。使用独立合成名单，在 375px 宽度下额外延迟每次工作台数据响应 2.5 秒，登录后成功进入菜单并点击学生名单显示 100 名演示学生。截图位于项目父目录 `reports/mobile-login-20261021/entered.png`，未使用真实账号密码或业务数据。
