# 照片与活动同步

所有账号使用同一学校数据库和照片存储。年级负责人已保存的活动、原始成绩、评级、活动序号和关联照片，院负责人查看本院，管理员查看全校；年级负责人继续只查看负责的小组。数据不会按账号复制成互不更新的副本。

新上传但尚未识别或归组的照片，会记录上传时的学院 ID，原上传者和管理员可处理，同院负责人可查看原图。尚未归组时院负责人仅查看，不代替原上传者重识别或删除。识别归组后，改为原有小组权限；多学院照片不会仅因上传学院标记就向某一学院开放整张图。

学院改名时共享仍有效；修改上传者的学院、改名、停用或删除账号不会把旧照片转给新学院。旧版未记录上传学院的未归组照片不根据账号当前学院猜测归属，仍由原上传者和管理员查看。旧照片一旦准确归组，沿用原有共享规则。

## 页面更新

保存或上传后刷新本账号数据；其他在线账号通常每 45–60 秒自动刷新，失败时退避重试。回到页面、恢复网络、结束编辑后会尽快重新读取。学期选择栏显示最近成功同步的时间，可点击“同步最新数据”。报错时提示同步未完成，不把旧数据标为最新。编辑中的成绩表暂停后台同步，保存或关闭后恢复，避免覆盖未保存输入。

同步依赖同一网址背后的同一数据库与照片存储。不同电脑各自启动的本地测试库不会互相同步。只有文件实际上传成功后才在服务器共享；等待选择、上传失败或尚未联网的照片不会被当作已保存。这里使用定时刷新，不承诺实时推送。

## 验证与回退

新增测试核对两个年级上传的未归组照片向院负责人和管理员共享、原图可读、同院其他年级隔离、归组后成绩和照片关联一致、账号改学院不改变旧照片归属。沿用已确认活动锁定、归档只读、冲突检查和受保护照片删除规则。

设置 `lib/flags.ts` 的 `collegePhotoSharing=false` 并重新构建，可关闭新增未归组照片共享、同步状态栏和结束编辑后的主动刷新；已经保存的学院标记保留，原有归组活动共享和定时刷新继续工作。新表 `intake_upload_scopes` 随迁移或本地首次访问创建。

修改前源码快照为项目父目录 `backups/source-before-photo-sync-20261021.zip`，已校验压缩包，不含学校业务数据库和照片。

本次验证：77 项单元测试通过，TypeScript、生产构建、三角色集成和并发写入回归通过。测试使用隔离数据库和照片存储，测试库结束后自动清理；不修改学校业务数据。本次不扩大既有在线人数或并发上传容量承诺。
